# Context Budget

[English](README.md) | [Русский](README.ru-RU.md)

Скилл, который минимизирует **расход входных токенов** при кодинге, отладке, ревью и исследовании кода: упаковывает много действий в один ход и жёстко ограничивает объём, который любой инструмент может вернуть — не пропуская обязательные проверки корректности.

**A/B-тест на полной сборке статического сайта (8 страниц, 9 ассетов, скрипт самопроверки): примерно на 50% меньше входных токенов со скиллом, чем без него.**

## Почему входные токены растут

Транскрипт пересылается как вход на каждом ходу и каждый раз оплачивается заново. Три вещи растят его безвозвратно — ничего не удаляется до самой компакции:

1. **Результаты инструментов** — каждое чтение файла, вывод каждой команды остаются в контексте до конца сессии.
2. **Собственные сообщения модели** — каждая строка нарратива, пересказ плана, вставленный сниппет и подробный ответ заново оплачиваются на каждом следующем ходу.
3. **Сами инструкции** — ещё одна причина держать скилл плотным.

Дополнительные ходы и лишние байты усиливают друг друга: каждый новый ход заново оплачивает всё, что уже в контексте, а каждый раздутый результат заново оплачивается каждым последующим ходом. Поэтому скилл требует **оба рычага одновременно**:

- **Меньше ходов** — упаковывать максимум независимых действий в каждый ход (спекулятивные цепочки мультидействий, запись всех файлов одним сообщением).
- **Меньше байт за ход** — жёсткий лимит на то, что инструмент может вернуть (чтения ~150 строк, ограниченный поиск, `tail -n 30` для вывода команд).

## Что делает скилл

| Секция | Правило |
|---|---|
| Правило хода | Спекулятивные цепочки: заранее предсказать всю последовательность действий, собрать все независимые вызовы (2, 5, 10, 20 файлов) в одно сообщение; при первом сюрпризе — откат в одношаговый режим. Запрещено между действиями: статусные сообщения, пересказ плана, «думанье вслух». |
| Жёсткие лимиты вывода | Чтения ≤ ~150 строк (300 = дефект), поиск `rg -m 20` / `head -n 40`, сначала `git diff --stat`, по умолчанию `2>&1 \| tail -n 30`, никогда полные логи/локфайлы/минифицированное/JSON-дампы, ни один результат не больше ~10k токенов. |
| Делегирование широкого поиска | Если честное исследование затянет в основной поток >~3 файлов / ~400 строк — отправить поискового субагента, который сожжёт свой одноразовый контекст и вернёт вывод <300 слов. Делегировать факты, а не контент, который сам будешь править. |
| Додумать в голове, потом выдать | Готовый код за один проход — импорты, обработка ошибок, тесты тем же Write. Один патч на файл. Никогда не перечитывать только что написанное. Все правки, вытекающие из новых результатов, складывать в следующий ход. |
| Проверить один раз, тихо | Один проверочный ход после всех записей, ограниченный вывод. Никогда не перезапускать уже прошедшую команду. |
| Гигиена сессии | Переиспользовать, не перезапрашивать. Ссылки `path:line` вместо цитирования. Две неудачные попытки = перестать латать, вывести причину заново. Выгружать долгоживущее состояние в notes-файл, который переживёт компакцию. |
| Непреложное | Плотность никогда не важнее корректности: не угадывать содержимое файлов, не пропускать тесты. Недочитанное чтение, которое заставит перечитать, дороже правильного чтения. |

## Установка

Скилл — это обычный `SKILL.md` (плюс опциональные метаданные интерфейса), без зависимостей и скриптов. Нативная поддержка **Agent Skills** есть в ZCode, Claude Code и Codex CLI. Для агентов на правилах ставится как постоянное правило.

### ZCode

```bash
git clone https://github.com/SoftArax/Context-Budget.git
cp -r Context-Budget ~/.zcode/skills/context-budget
```

На уровне пользователя (во всех рабочих папках). Для одного проекта — скопируйте в `<проект>/.zcode/skills/context-budget`.

### Claude Code

```bash
git clone https://github.com/SoftArax/Context-Budget.git
cp -r Context-Budget ~/.claude/skills/context-budget
```

Формат тот же (`SKILL.md` с frontmatter `name`/`description`) — Claude Code подхватит скилл автоматически и будет применять по мере уместности; можно вызвать и явно через `/context-budget`. Для одного проекта — в `<проект>/.claude/skills/context-budget`.

### Codex CLI

```bash
git clone https://github.com/SoftArax/Context-Budget.git
cp -r Context-Budget ~/.codex/skills/context-budget
```

`agents/openai.yaml` добавляет метаданные интерфейса (отображаемое имя, краткое описание, промпт по умолчанию).

### Cursor

Agent Skills не поддерживаются; ставим как постоянное правило проекта:

```bash
git clone https://github.com/SoftArax/Context-Budget.git
mkdir -p .cursor/rules
{ printf -- '---\ndescription: Minimize input-token cost: many actions per turn, hard-capped tool output\nglobs: \nalwaysApply: true\n---\n\n'; tail -n +5 Context-Budget/SKILL.md; } > .cursor/rules/context-budget.mdc
```

Закоммитьте правило в репозиторий, чтобы оно было у всей команды.

### Windsurf

```bash
git clone https://github.com/SoftArax/Context-Budget.git
mkdir -p .windsurf/rules
tail -n +5 Context-Budget/SKILL.md > .windsurf/rules/context-budget.md
```

Добавьте тело скилла в свой контекстный файл:

```bash
git clone https://github.com/SoftArax/Context-Budget.git
tail -n +5 Context-Budget/SKILL.md >> ~/.gemini/GEMINI.md
```

### Cline / Roo Code

```bash
git clone https://github.com/SoftArax/Context-Budget.git
mkdir -p .clinerules   # Roo Code: .roo/rules/
tail -n +5 Context-Budget/SKILL.md > .clinerules/10-context-budget.md
```

### Всё, что читает AGENTS.md

Вставьте тело `SKILL.md` (всё после frontmatter) в свой `AGENTS.md` — скилл написан агент-независимо и работает везде, где модель читает инструкции проекта.

> Примечание: секция про делегирование субагентам работает только там, где субагенты есть. В остальных агентах она просто ничего не делает.

## Методика A/B-теста

Одну и ту же большую задачу — собрать законченный статический сайт аналитического SaaS на 8 страниц (HTML + CSS + vanilla JS, 4 стилей, 5 скриптов, самопроверка `tools/check.py`, README) — выполняли два одинаковых агента в изолированных папках: один со скиллом, другой без. Метрики считались по транскриптам model-I/O (запросы и расход токенов по каждому вызову API), а не по самоотчётам.

**Результат: примерно на 50% меньше входных токенов со скиллом.** Меньше ходов (пакетные записи/поиски вместо «один маленький шаг — один ход») и меньшие результаты за ход (лимиты на чтения, ограниченный вывод поиска) усиливают друг друга: каждая сэкономленная строка перестала оплачиваться всеми последующими ходами, в которых она иначе дожила бы до конца.

## Замечания и честные ограничения

- Скилл сокращает **ходы модели/инструментов**, а не клиентские HTTP-запросы: отправлять параллельные вызовы инструментов одним или несколькими API-запросами решает клиент.
- Лимиты подобраны ради экономии; на действительно огромных файлах используйте точечные чтения `offset/limit` или извлечение через shell вместо чтения целиком.
- Плотность никогда не важнее корректности — протокол явно разрешает дополнительные ходы и большие чтения, когда проверке они действительно нужны.
